# State protocol

OVCAQ state is a closed, versioned JSON document. Durable mutations go through
the state store; agents and provider adapters do not edit `state.json` directly.
The current protocol version is `1`.

## V1 shape

The owned top-level objects are `batch`, `work`, `tasks`, `review`,
`control`, and `recovery`. Provider-specific state stays at adapter or event
boundaries. Raw session evidence survives normalization outside this document.

`new_state()` creates revision zero, an idle batch, build as both current and
next phase, empty task and review collections, review cap three, and a resolved
absolute repository root. Optional values start null.

Validation is closed at owned objects. Counts and identifiers reject booleans,
timestamps use UTC RFC 3339 with `Z`, and open extension maps contain finite
JSON values only. The implementation constants define byte, depth, task,
attempt, review, capability, and open-map limits. JSON text is depth-preflighted
before recursive decoding and duplicate object keys are rejected at every
level before closed-schema validation can collapse them.

## Owned field constraints

Every owned object is closed: all fields below are required and unknown fields
are rejected. Optional means the value may be null, not that the key may be
omitted.

### State

- `State.schema_version`: integer equal to the current protocol version.
- `State.revision`: non-boolean integer greater than or equal to zero.
- `State.batch`: required validated `BatchState` object.
- `State.work`: required validated `WorkState` object.
- `State.tasks`: required list of validated task objects, limited to 512 entries.
- `State.review`: required validated `ReviewState` object.
- `State.control`: required validated `ControlState` object.
- `State.recovery`: required validated `RecoveryState` object.

### Batch state

- `BatchState.id`: string identifier; empty only while the batch is idle.
- `BatchState.status`: one of idle, running, attention, or completed.
- `BatchState.started_at`: optional UTC RFC 3339 timestamp.
- `BatchState.completed_at`: optional UTC RFC 3339 timestamp, required for completion.
- `BatchState.completed_prds`: required list of validated completed-PRD records.
- `BatchState.parks_consecutive`: non-boolean integer greater than or equal to zero.
- `BatchState.catchup`: required validated catch-up cache object.
- `BatchState.capabilities`: required capability map limited to 64 entries.
- `CatchupCache.completed_at`: optional UTC RFC 3339 completion timestamp.
- `CatchupCache.head_sha`: optional string commit identifier.
- `CompletedPrd.filename`: required string PRD filename.
- `CompletedPrd.cycles`: non-boolean non-negative cycle count.
- `CompletedPrd.autonomous_decisions`: non-boolean non-negative decision count.
- `CompletedPrd.escalated_decisions`: non-boolean non-negative escalation count.
- `CompletedPrd.tasks_completed`: non-boolean non-negative count not exceeding total tasks.
- `CompletedPrd.tasks_total`: non-boolean non-negative total task count.

- `WorkState.extensions`: open extension map with validated keys and finite JSON values.
- `TaskEntry.id`: unique non-boolean integer greater than or equal to one.

- `TaskEntry.description`: required task-description string.
- `TaskEntry.active_form`: required active-form string.
- `TaskEntry.status`: one of `pending`, `in_progress`, or `completed`.

### Capabilities

- `CapabilityEntry.required`: required boolean capability marker.
- `CapabilityEntry.launcher`: required launcher-name string.
- `CapabilityEntry.plugin`: required plugin-identifier string.
- `CapabilityEntry.version`: required plugin-version string.
- `CapabilityEntry.failure`: fixed attention failure policy.
- `CapabilityEntry.status`: pending, running, failed, succeeded, or skipped status.
- `CapabilityEntry.attempts`: ordered list of validated capability attempts.
- `CapabilityAttempt.id`: globally unique attempt-identifier string.
- `CapabilityAttempt.status`: running, failed, or succeeded attempt status.
- `CapabilityAttempt.started_at`: required UTC RFC 3339 timestamp.
- `CapabilityAttempt.finished_at`: optional UTC RFC 3339 completion timestamp.
- `CapabilityAttempt.session_id`: optional session-identifier string.
- `CapabilityAttempt.detail`: optional attempt-detail string.

Capability status and attempts move together: pending and skipped have no
attempts, skipped is allowed only for optional capabilities, running has an
unfinished latest running attempt, and terminal capability states have a
finished latest attempt with the same status. Earlier attempts are terminal and
chronologically ordered. A completed batch requires every required capability
to have succeeded.

## Transaction and restore contract

Reads take a shared read lock. A transaction takes an exclusive mutation lock,
while restore takes an exclusive restore lock. Both use compare-and-set on
`expected_revision` before publication. A transaction invokes its mutator
exactly once on an isolated state copy; the store-owned revision produces a
monotonic revision even when the mutator supplies another value.

Publication writes canonical JSON with UTF-8 encoding, two-space indentation,
and a trailing newline. Raw backup bytes preserve the previous committed bytes.
Every temporary file receives a file fsync before replacement, followed by a
parent-directory fsync. Publication failure repair restores the captured state
and backup while the exclusive lock remains held.

Restore validation covers both current state and the raw backup. Restore creates
a new commit with the next revision, then rotates the pre-restore current bytes
into the backup through the same durable publication path.

Public restoration refuses active recovery except an unbound `intent` whose
`artifact` is null. That older invalid intent cannot pass the move's identity
check; `state restore` can recover its pre-intent backup without touching PRD
files. Recovery with a captured artifact, or at the `moved` or `recorded` step,
must reconcile before restoration. Other state mutations remain fenced even
for unbound intents.

The derived project runtime remains under the resolved project root. Existing
symlinks in `docs/dev/project-management/ovcaq` are rejected before initialization creates,
changes permissions on, or writes through them. The state, backup, and lock
artifacts must be single-linked regular files. They are rejected by a
non-following metadata check before open, opened without following symlinks,
and verified against their opened file descriptors before use. State and backup
reads use nonblocking opens so a type-changing race cannot turn the read into a
FIFO wait. Multi-linked artifacts are rejected before reads, permission
changes, rotation, restore, or publication can touch an external alias.

## Stable symbolic errors and exit codes

Each stable symbolic error maps to one documented exit code.

Excessive JSON nesting and integer literals or programmatic integer values
longer than 640 digits are `resource_limit`; malformed, duplicate-key, or
non-standard-constant durable state is `state_io`; malformed, duplicate-key,
non-standard-constant, over-deep, or oversized-integer backup JSON is
`invalid_backup`. Inline and file payload syntax errors, including duplicate
keys and `NaN`/`Infinity` constants, are `usage`; their oversized integer
literals remain `resource_limit`.

| Symbolic error | Exit code |
| --- | ---: |
| `usage` | 1 |
| `invalid_state` | 1 |
| `state_io` | 2 |
| `future_schema` | 6 |
| `state_exists` | 7 |
| `invalid_backup` | 8 |
| `revision_conflict` | 9 |
| `invalid_path` | 1 |
| `protected_path` | 1 |
| `durability_unsupported` | 10 |
| `resource_limit` | 11 |
| `oversized_plan` | 3 |
| `runtime_format` | 1 |
