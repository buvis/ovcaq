### Problem Statement

Tracon observes useful state but parses Claude-native streams and duplicates
process/registry behavior, while Bash owns run/attach job control. OVCAQ needs
one optional provider-neutral TUI and Python launcher using shared runtime models.

### Target User

The operator needs fleet/detail visibility, safe controls, detach/reattach, and
plain fallback without affecting supervisor correctness.

### Success Metrics

- TUI crash or detach leaves the supervisor and owned agent tree alive.
- Pause/stop affect exactly the selected run through public services.
- No duplicate registry, liveness, workflow policy, or provider decoder remains.
- `ovcaq run`/`attach` require no Bash; no-TUI works when Textual fails.
- Unknown/raw-only providers remain visibly degraded rather than fabricated.

## Preconditions and Boundaries

- Depends on completed PRDs 00002–00007.
- The TUI observes shared state, registry, metrics, and normalized observations.
- It does not decide lifecycle transitions or maintain independent liveness.
- Clipboard/platform extras are excluded unless isolated behind a capability
  adapter; correctness never depends on them.

## Functional Decomposition

### Capability: Shared Read Models

#### Feature: Fleet and project discovery

Project fleet/detail views consume the atomic runtime registry and state/session
models, including stale-safe selection and explicit provider identity.

#### Feature: Tolerant live projections

Tail state, normalized events, metrics, and raw fallback with inode/truncation
handling. Missing/corrupt/partial observational data degrades without crashing.

### Capability: Operator Presentation

#### Feature: Workflow and activity panels

Present phase, tasks, review cycles, activity lanes, duration, usage, cost when
known, failure/parking/stopping/halt status, and telemetry capability gaps.

#### Feature: Post-drain capability status

Show pending/running/failed/succeeded/skipped state, failure attention, retained
evidence, and the exact independent retry command.

### Capability: Python Run and Attach

#### Feature: Safe controls

Detach, boundary pause, resume/reattach, confirmed stop, help, and selection call
public runtime/state services for exactly one run; `attach` never starts another
supervisor. The accepted controls remain `q` detach, `p` boundary pause, and
confirmed `s` stop.

#### Feature: TTY and fallback lifecycle

Interactive `ovcaq run` starts the owned background supervisor and attaches by
default. `q` detaches. Non-TTY/`--no-tui` remains foreground. Textual startup or
runtime failure falls back to the plain renderer without killing the supervisor.

## Design Doc

# Design: OVCAQ TUI and Python launcher

## Architecture fit

PRD 00008 fills the intentionally empty `ovcaq.tui` boundary and replaces the
remaining Bash-owned launch/attach presentation with Python. It sits above the
stable PRD 00003–00007 services: `StateStore` remains the only workflow-state
reader/writer boundary; `FleetRegistry` and `observe_run()` remain the only
process/liveness authorities; `Observation`, `SessionMetric`, and capability
state remain the telemetry contracts; `StateService` and the verified stop
service remain the only control paths. The TUI derives no transition, liveness,
provider, or retry policy of its own.

The supervisor remains an independently owned process. On an interactive TTY,
`ovcaq run` starts a detached Python child running the existing foreground
supervisor path, waits for the shared registry/run-lock handshake, and then
attaches the viewer. `q`, EOF, `SIGINT`, a Textual crash, or a terminal loss can
end or replace only the viewer; none signal the supervisor. `ovcaq run --no-tui`
and non-TTY `ovcaq run` continue to run the supervisor in the foreground.
`ovcaq attach` observes an existing registry entry and never launches one.

The design introduces no state-schema migration. Observable state is read from
the existing v1 schema; unknown/malformed observational records become explicit
telemetry gaps. CLI compatibility is still pre-stability under the accepted
implementation plan: this PRD updates generated command documentation and tests,
while the stable public compatibility/versioning policy remains Phase 12 work.
Rollback is ordinary Git rollback; the state shape is unchanged, detached
supervisors retain their evidence, and `ovcaq stop` remains the recovery path for
an intentionally terminated run. The repository owner is the human operator.

## Interfaces & contracts

`src/ovcaq/events/tail.py` adds the read side without changing
`RawFirstDecoder`:

```python
T = TypeVar("T")

@dataclass(frozen=True, slots=True)
class TailGap:
    kind: Literal["missing", "replaced", "truncated", "malformed", "oversized"]
    detail: str

@dataclass(frozen=True, slots=True)
class TailBatch(Generic[T]):
    records: tuple[T, ...]
    gaps: tuple[TailGap, ...]
    reset: bool
    backlog: bool
    complete_history: bool

class JsonlFollower(Generic[T]):
    def __init__(
        self,
        path: Path,
        decode: Callable[[Mapping[str, JSONValue]], T],
        *,
        max_record_bytes: int = MAX_STATE_BYTES,
        replay_bytes: int = 256 * 1024,
        max_read_bytes: int = 1024 * 1024,
        max_records: int = 1024,
    ) -> None: ...
    def read(self) -> TailBatch[T]: ...
    def close(self) -> None: ...
```

`JsonlFollower.read()` opens with `O_NOFOLLOW`, validates a regular file, and
retains at most `max_record_bytes + 1` bytes for one unfinished record. Each
call consumes at most `max_read_bytes` and returns at most `max_records`, leaves
the offset at the first unread byte, and sets `backlog=True` plus a visible gap
when more data remains. On first attach it reads only the last `replay_bytes`,
discarding the initial partial
line. A same-inode size decrease resets to offset zero and emits `truncated`; an
inode change closes/reopens and emits `replaced`; a missing file emits `missing`
without raising. Each complete UTF-8 JSON object is passed to `decode`.
Malformed/oversized rows emit a gap and later records continue. The follower
never writes, deletes, prunes, or interprets provider-native JSON.

`complete_history` is true only when this follower has observed the file from
offset zero since its most recent open/reset. On `reset=True`, consumers discard
all accumulated records before applying the batch. A tail-window attach sets
`complete_history=False`; consumers may show recent activity but may not report
totals or lane absence as complete evidence.

`src/ovcaq/runtime/session.py` exposes the existing metric validation:

```python
def metric_from_record(record: Mapping[str, JSONValue]) -> SessionMetric: ...

@dataclass(frozen=True, slots=True)
class MetricsSnapshot:
    rows: tuple[SessionMetric, ...]
    complete: bool
    gaps: tuple[str, ...]

def observe_metrics(
    paths: RuntimePaths,
    *,
    batch_id: str,
    max_bytes: int = 16 * 1024 * 1024,
    max_records: int = 4096,
) -> MetricsSnapshot: ...
```

It requires the exact `SessionMetric` field set and the same completion/usage
invariants used by metric publication. Publication and reconciliation call this
function too, leaving one schema definition.
`SessionMetric.usage` is a cumulative snapshot for one session, not a delta.
Batch totals sum one final row per session only when `observe_metrics()` read
the complete aggregate file within both caps. Otherwise batch usage is `None`
with a visible partial-metrics gap; the latest session's cumulative usage may
be shown separately as partial. Active-run duration comes from registry
`started_at`, never by summing an incomplete tail.

`src/ovcaq/tui/discovery.py`:

```python
@dataclass(frozen=True, slots=True)
class FleetRun:
    run_id: str
    root: Path
    agent: str
    started_at: str
    pid: int
    process_start: str

@dataclass(frozen=True, slots=True)
class FleetView:
    runs: tuple[FleetRun, ...]
    malformed_entries: tuple[Path, ...]
    stale_entries: tuple[Path, ...]

def discover_fleet(registry: FleetRegistry) -> FleetView: ...
def select_run(view: FleetView, *, run_id: str | None, root: Path | None) -> FleetRun: ...
```

`discover_fleet()` calls `FleetRegistry.snapshot()` exactly once and sorts only
its already-live entries by `(root, started_at, run_id)`. It does not call
`process_identity()`, inspect `ps`, take the run lock, or prune. `select_run()`
requires one exact match; zero or multiple matches raise `ValueError` naming the
available run IDs and roots. A project-detail attach is therefore bound to one
registry identity rather than a path that could silently switch owners.
Every observer and control retains this full `FleetRun`. Immediately before a
poll or control action it requires an exact live registry match on run ID, root,
PID, and process-start token; replacement detaches/fails closed.

```python
    next_phase: NextPhase | None
    prd: str | None

    tasks_completed: int | None
    tasks_total: int | None
    review_cycle: int | None
    provider: str
    duration_seconds: float | None
    usage: UsageView | None

    capabilities: tuple[CapabilityView, ...]
    attention: Notice | None
    telemetry: TelemetryLevel
    gaps: tuple[str, ...]

    def __init__(self, run: FleetRun, settings: RuntimeSettings) -> None: ...
    def poll(self) -> ProjectView: ...
    def close(self) -> None: ...

def display_text(value: str, *, limit: int = 512) -> str: ...
```

`ProjectObserver.poll()` first revalidates its exact `FleetRun`, then reads
`StateStore.read()`, `observe_run()`, aggregate metrics through
`observe_metrics()`, and normalized observations
through `JsonlFollower(observation_from_record)`. It also calls the shared
read-only `observe_session_evidence()` for the active session and
`observe_emergency_failure()` for state-write-failure evidence. It catches observational
`StateError`, schema, JSON, and I/O failures into `gaps`; it never mutates state.
State supplies phase/tasks/review/capabilities/control status. Registry/run
observation supplies liveness. Metrics supply duration/model/usage. Normalized
observations supply provider, lane, activity, and failure detail. A
`raw.unknown` or `SessionEvidenceStatus(raw=True, normalized=False)` yields
`raw-only`, including a crash between raw persistence and normalization;
missing data yields `partial`/`unavailable`; absent numeric telemetry stays
`None`. Capability failures expose exactly
`("ovcaq", "--root", str(root), "capability", "retry", name)`.

`display_text()` removes C0/C1 controls (including ESC, BEL, CR, and OSC
framing), preserves newline only where a panel explicitly allows it, and caps
length before any dynamic agent/state/evidence text enters a view. Panels wrap
every dynamic value in `rich.text.Text`; they never pass it through Rich markup
parsing. Static styles are applied programmatically. This covers lane labels and
details, notices, capability details/names, PRD/provider text, and gap strings
in both Textual and plain output.

The status precedence is: state-write-failure emergency evidence; inconsistent
shared run observation; stopping signal evidence; recovery park/stall; durable
pause request; durable attention/failed required capability; paused phase;
completed batch; active run; unknown/idle.
This is presentation precedence only. It never chooses a workflow action or
claims liveness independently of `observe_run()`/`FleetRegistry`.

The observer retains at most 256 lanes and 128 distinct gap strings. Terminal
lanes are evicted oldest-first before active lanes; excess gaps collapse into
one `additional telemetry gaps omitted` entry. Poll backlogs remain visible and
drain over later polls, bounding both per-poll work and retained projection
memory.
On every follower `reset`, accumulated lanes and latest-session usage are
cleared before applying new records. When normalized history is incomplete, a
progress/completion event without a prior start creates an explicit `unknown`
lane and the view carries a partial-history gap; lane absence is never presented
as proof that no lane exists.

`src/ovcaq/supervisor_cli.py`:

```python
@dataclass(frozen=True, slots=True)
class LaunchedSupervisor:
    run: FleetRun

def stop_supervisor(run: FleetRun) -> ProcessIdentity: ...
def launch_supervisor(
    root: Path,
    *,
    agent: str | None,
    argv_prefix: tuple[str, ...] = (sys.executable, "-m", "ovcaq"),
    timeout_seconds: float = 10.0,
) -> LaunchedSupervisor: ...

@dataclass(frozen=True, slots=True)
class LaunchFailureEvidence:
    exit_code: int | None
    detail: str
    path: Path
```

`stop_supervisor(run)` is the current `_stop()` verification strengthened to
require the caller's exact selected identity: run metadata, matching live fleet
entry, process start identity, and held run lock must all agree before
`SIGTERM`. `launch_supervisor()` resolves/creates the runtime layout, builds
`(*argv_prefix, "--root", str(root), "run", "--no-tui")`, appends
`("--agent", agent)` only when `agent is not None`, and starts it with
`stdin=DEVNULL`, `stdout=DEVNULL`, `stderr=DEVNULL`,
`start_new_session=True`, `close_fds=True`, and `shell=False`, then polls shared
registry/run observation until the fleet entry PID and process-start token match
the spawned child's PID and observed start token. It returns that exact
`FleetRun`; an unrelated owner cannot satisfy the handshake. Child
exit, timeout, zero/multiple owners, or an inconsistent run returns a bounded
actionable error and never starts a replacement. After the handshake, viewer
exit does not retain a `Popen` context manager and therefore cannot terminate
the child.

The parent creates a one-shot launch-report path under the 0700 runtime root and
passes it through the narrowly internal `OVCAQ_LAUNCH_REPORT` environment key.
Before registry publication, the child CLI catches every dispatch/config/layout
failure and atomically publishes at most 4096 sanitized UTF-8 bytes to that
`O_NOFOLLOW`, 0600 regular file. On handshake success it removes the report;
on early exit/timeout the parent includes its bounded contents and path in
`LaunchFailureEvidence`. stdout/stderr remain `DEVNULL`, so no stream can grow
without bound, while pre-publication failures remain diagnosable.

`src/ovcaq/tui/app.py`:

```python
class ControlService(Protocol):
    def pause(
        self, run: FleetRun, expected_revision: int, reason: str | None = None

    def resume(self, run: FleetRun, expected_revision: int) -> None: ...
    def stop(self, run: FleetRun) -> ProcessIdentity: ...

@dataclass(frozen=True, slots=True)
class AttachResult:
    reason: Literal["detached", "completed", "fallback", "failed"]
    exit_code: int

def attach(
    *,
    registry: FleetRegistry,
    root: Path | None,
    run_id: str | None = None,
    controls: ControlService,
    poll_interval: float = 0.25,
) -> AttachResult: ...

def run_plain(
    observer: ProjectObserver,
    *,
    poll_interval: float = 0.25,
) -> AttachResult: ...

def run_plain_fleet(
    view: FleetView,
    *,
    input_stream: TextIO,
    output_stream: TextIO,

```

`attach(root=None)` opens the fleet view and lets the user choose one live
entry; an explicit root/run ID opens exactly that detail view. Project bindings
are `q` detach, `p` request boundary pause through `StateService`, `s` open a
confirmation dialog and then call `stop_supervisor()`, and `?` help. `Ctrl-C`
and terminal EOF detach; they never call stop. A Textual import/start/runtime
failure closes only UI resources, writes one concise fallback notice, and calls
`run_plain()` against the same selected `ProjectObserver`. If fleet-mode
Textual fails before selection, `run_plain_fleet()` prints a numbered immutable
`FleetView` and accepts one bounded line selecting a run ID; EOF/interrupt
detaches. Plain project mode redraws
`plain_frame()` while the run is live, exits on completion, and treats
`KeyboardInterrupt` as detach. A viewer failure returns nonzero but leaves the
supervisor alive.

Pause/resume use the revision from the last `ProjectView` as
`StateService`'s `expected_revision`. The control service validates the exact
`FleetRun` immediately before the compare-and-set mutation and immediately
after it; a revision conflict or changed identity fails closed and is reported
as stale selection. Stop keeps the stronger PID/run-lock proof above.

Theme loading/writing uses
`${XDG_CONFIG_HOME:-~/.config}/ovcaq/theme`; invalid/unavailable theme files are
ignored with a visible gap and never block attach. No clipboard integration is
implemented in this PRD.

`src/ovcaq/cli.py` changes the live parser contract to:

```text
ovcaq [--root PATH] run [--agent NAME] [--no-tui]
ovcaq [--root PATH] attach [--run-id ID]
```

For `run`: `--no-tui` or non-TTY calls the existing foreground `_run()` path.
An interactive TTY calls `launch_supervisor()` then attaches by its returned
exact `FleetRun`. For
`attach`: `--root` binds project detail; without `--root`, the fleet view is
shown. `attach` never calls `launch_supervisor()`. The JSON mode rejects
interactive `run`/`attach` and requires `run --no-tui`; stable machine output
does not mix with terminal control sequences. Existing `pause`, `resume`, and
`stop` keep their machine contracts. `resume` clears pause through
`StateService`; on an interactive terminal without `--json`, it revalidates and
attaches when the same supervisor remains live. When a boundary pause already
ended that supervisor, it calls `launch_supervisor()` exactly once and attaches
to the returned identity. Child-exit, duplicate-owner, or handshake failure is
reported and never retried by starting another process.

## Data flow

Interactive `ovcaq run` resolves project/runtime configuration, spawns the
foreground supervisor command as a detached Python child, and waits only for
the authoritative run-lock/registry handshake. The child owns the agent process
group and writes state, raw/normalized session evidence, aggregate metrics,
run metadata, and fleet registration. The parent opens an observer over those
artifacts and passes immutable projections to Textual or Rich. Detaching drops
the observer only; the child continues until its own decision table terminates.

`ovcaq attach` starts at `FleetRegistry.snapshot()`. Fleet selection produces a
`FleetRun`, `ProjectObserver` resolves that root's runtime paths, and each poll
combines state plus normalized observational deltas into a `ProjectView`.
Panels consume only that view. Pause/resume commit through `StateService`; stop
revalidates registry, run metadata, process identity, and lock before signaling.

Normalized JSONL follows this path:
`SessionEvidenceWriter -> RawFirstDecoder -> Observation record ->
JsonlFollower -> ProjectObserver lane/usage projection -> panels`. Invalid or
unknown rows remain visible as gaps/raw-only status and never affect supervisor
decisions.

## Alternatives considered

1. Chosen: a detached foreground-supervisor child plus one shared projection
   model for Textual and plain Rich. This gives UI-independent process
   ownership, direct reuse of runtime authority, testable detach semantics, and
   no permanent daemon/protocol.
2. Smallest diff: run `Supervisor.run()` in a background thread inside the TUI
   process and let `q` hide the UI. Rejected because process lifetime would
   still belong to the viewer; crashes, interpreter exit, signal routing, and
   terminal teardown could kill or corrupt the supervisor.
3. Add a long-lived local daemon/socket and make every CLI a client. Rejected as
   an unnecessary new authority and protocol for a solo, single-host cutover.
   The existing run lock, registry, state, and signals already provide the
   required coordination.

## Risks & edge cases

- The parent can race child publication or child failure. The handshake is
  bounded, checks child exit and the child's PID/process-start identity, and
  never retries by launching another child or accepting an unrelated owner.
- PID reuse, selected-run replacement, or a replaced `run.json` could target the
  wrong process. Observers and controls immediately revalidate the immutable
  selection; stop keeps all four existing proofs: registry entry, root/run ID,
  process-start token, and held run lock.
- Logs can rotate, truncate, end mid-record, exceed bounds, or contain malformed
  JSON. `JsonlFollower` resets safely, bounds memory, emits gaps, and continues.
- State may be unreadable while evidence remains live, or events/metrics may lag
  state. Projection fields remain independently unknown; state remains
  authoritative and the UI never fills gaps from agent prose.
- Textual can import but fail after mounting. The top-level attach runner catches
  startup/runtime failures, closes the app observer, and enters plain mode
  without touching the supervisor.
- A detached child has no terminal streams. Its durable state, per-session raw
  and normalized evidence, metrics, summaries, attention, and exit decisions
  remain the observability surface; launch handshake failures are reported by
  the parent before detach.
- Multiple fleet runs make root-free attach ambiguous by design: fleet mode
  requires selection. Root/run-ID selection fails closed rather than choosing
  the newest process.
- Likely next changes are PRD 00009 Codex observations, PRD 00010 provisioning
  status, and the personal cutover. The projection uses provider-neutral enums,
  preserves unknown events, and renders generic capability entries, so those
  changes do not require TUI policy branches.
