# OVCAQ supervisor loop

Status: backlog | Version: 1 | Umbrella phase: 5 | Created: 2026-08-23

## Overview

### Source Contract

Implements Phase 5 source tasks `P05-T01`–`P05-T09` and every phase exit
criterion from the [accepted implementation plan](../../plans/implementation-plan.md).
The [coverage manifest](../implementation-plan-coverage.md) and [resolved shared
discovery 00001](../../discovery/00001-ovcaq-v1.md) are mandatory inputs.
Grouped wording below never waives or renumbers a source obligation.

### Problem Statement

The current loop contains proven routing, retry, pause, park, drain, metrics,
and post-drain behavior but mixes provider details with orchestration. OVCAQ
needs a state-led supervisor that runs without Bash and explains every next
action from committed state plus a normalized session result.

### Target User

Operators need a reliable headless runner; agents need fresh phase sessions;
later UI code needs one authoritative supervisor rather than duplicate policy.

### Success Metrics

- A fake Claude driver drains build/review/done through `ovcaq run --no-tui`.
- Every continuation and halt is a tested pure decision from state plus summary.
- The full legacy loop/parity inventory has one implemented or retired outcome.
- Exactly one metric row is emitted per attempted session.
- Agoge failure preserves drained PRDs and retries independently.

## Preconditions and Boundaries

- Depends on completed PRDs 00002–00006.
- State and workflow services own durable transitions; drivers own provider data.
- This PRD provides foreground/no-TUI operation only; interactive attachment is
  PRD 00008.
- Agent final prose is never authoritative.

## Functional Decomposition

### Capability: Pure Post-Session Decisions

#### Feature: Ordered decision table

Compare pre/post state revision and fingerprints; let valid progress win over
provider exit noise; then evaluate pause, capabilities, completion, continuation,
rate limit, retry, repeated fingerprints, park, and systemic halt in that order.

#### Feature: Bounded failure policy

Classify credible provider rate limits, connectivity loss, timeout, process
death, permission/authentication failure, bootstrap failure, and repeat stalls.
All waits/retries/caps come from configuration and injectable time.

### Capability: Session Orchestration

#### Feature: Phase routing and execution

Resolve phase-specific agent/model/effort/timeout configuration, create one
fresh session, snapshot state, invoke the driver through runtime process/session
services, then reduce the result and execute exactly one decision. Routing
configuration is provider-neutral: `[phases.PHASE]` names tier, effort, and
timeout; `[agents.NAME.tiers]` maps tier keys to provider model identifiers;
`[agents.NAME.phases.PHASE]` may override tier or effort; the per-agent prompt
template lives in agent configuration with a driver-provided default. Drivers
map the neutral effort scale to their native control and never drop it
silently.

#### Feature: Lifecycle controls and evidence

Honor boundary pause, resume by clearing durable pause intent, immediate stop,
drain/archive, provider-neutral durable attention projected by the TUI,
raw/normalized logs, and one metrics row per session. The current personal
`notify_out` OS-script path is retired rather than copied. Fail closed if state
is unreadable.

### Capability: Post-Drain Capabilities

#### Feature: Durable generic lifecycle

For non-empty drain, move required capability through pending/running/failed/
succeeded; persist unique attempts and actionable attention. Empty batches mark
it skipped. Completed batch requires all required capabilities satisfied.

#### Feature: Independent agoge retry

`ovcaq capability retry agoge` reconciles stale running ownership, refuses a
live owner, creates an idempotent attempt, and never reopens drained PRD phases.

## Test Strategy

- Productive state plus nonzero exit; untouched state plus success prose.
- Pause/resume/stop, next phase, empty/non-empty drain, and completed capabilities.
- Rate limit with/without credible reset; bounded connectivity/death/timeout.

## Design Doc

# Design: OVCAQ supervisor loop

## Architecture fit

PRD 00007 fills the two empty Phase 5 runtime seams: `runtime/decision.py` owns
the pure post-session table and `runtime/supervisor.py` owns orchestration and
effects. It composes the already-landed `StateStore`, workflow transitions and
park saga, owned process groups, watchdog, private session evidence, normalized
`SessionSummary`, driver registry, and runtime/fleet registry. Provider-native
argv, events, models, and failure parsing remain in `drivers/`; the supervisor
sees only driver protocol objects and normalized failures.

The state store remains the sole durable workflow writer. Supervisor and
capability state changes are compound `StateService` methods, never direct JSON
edits or independent writes. The one-writer boundary is an intentional single
point of serialization backed by the existing advisory lock, byte-for-byte
backup, atomic replacement, fsync, and tested restore path. The operator is the
human owner; `status`, `doctor`, retained raw/normalized evidence, session
summaries, metrics, `control.attention`, and command exit codes provide
observable operation.

The existing v1 state schema already carries `batch.status`,
`batch.capabilities`, `control.pause_requested`, `control.pause_reason`,
`control.attention`, `recovery.phase_fingerprint`, and
`recovery.phase_repeats`, so this PRD needs no state-schema migration. It adds
closed compound mutations over those fields. An empty drain atomically changes
each pending capability from `required=true` to `required=false` and
`status="skipped"`, which matches the existing invariant that only applicable
capabilities are required; this is an ordinary value transition, not a shape or
version change. Initial cutover remains one-way:
there is no legacy importer or rollback framework. Code rollback uses ordinary
Git; durable state recovery uses `StateStore.restore()`, and tests prove that a
failed mutation leaves state and backup byte-identical.

The authoritative parity source is
`tests/characterization/current_system.toml` filtered through
`tests/characterization/migration.toml` rows owned by PRD 00007. A checked-in
Phase 5 matrix records each routed ID as implemented or explicitly retired;
tests fail on a missing, duplicate, or unrecognized disposition.

## Interfaces & contracts

`src/ovcaq/runtime/decision.py`:

```python
class DecisionKind(StrEnum):
    PAUSE = "pause"
    RUN_CAPABILITY = "run_capability"
    SKIP_CAPABILITIES = "skip_capabilities"
    COMPLETE = "complete"
    CONTINUE = "continue"
    WAIT = "wait"
    RETRY = "retry"
    PARK = "park"
    HALT = "halt"

@dataclass(frozen=True, slots=True)
class SupervisorPolicy:
    died_retries: int
    connectivity_retries: int
    rate_limit_retries: int
    connectivity_wait_seconds: float
    rate_limit_wait_seconds: float
    phase_repeat_limit: int

@dataclass(frozen=True, slots=True)
class ProgressSnapshot:
    revision: int
    batch_id: str
    batch_status: BatchStatus
    prd: str | None
    phase: Phase
    next_phase: NextPhase
    pause_requested: bool
    pause_reason: Notice | None
    attention: Notice | None
    recovery_operation: RecoveryOperation | None
    tasks_completed: int
    review_cycle: int
    completed_prds: int
    drained: bool
    capabilities: Mapping[str, CapabilitySnapshot]
    phase_fingerprint: str | None
    phase_repeats: int

@dataclass(frozen=True, slots=True)
class AttemptResult:
    summary: SessionSummary
    started_at: datetime
    finished_at: datetime
    state_after: ProgressSnapshot | None
    state_error: str | None

@dataclass(frozen=True, slots=True)
class RetryState:
    died: int = 0
    connectivity: int = 0
    rate_limit: int = 0

@dataclass(frozen=True, slots=True)
class SupervisorDecision:
    kind: DecisionKind
    reason: str
    wait_seconds: float | None = None
    capability: str | None = None
    next_phase_repeats: int | None = None

def snapshot(state: State) -> ProgressSnapshot: ...
def progress_fingerprint(state: State) -> str: ...
def decide(
    before: ProgressSnapshot,
    result: AttemptResult,
    retries: RetryState,
    policy: SupervisorPolicy,
    *,
    now: datetime,
) -> SupervisorDecision: ...
```

`CapabilitySnapshot` is an immutable record with `required: bool`,
`status: CapabilityStatus`, `latest_attempt_id: str | None`, and
`latest_session_id: str | None`. Runnable required capabilities are selected by
lexicographically sorted name, so multiple entries produce one deterministic
next action.

`ProgressSnapshot.drained` is derived only from `work.next_phase == ""` after
the workflow drain transition. `completed_prds == 0` defines an empty drain,
including a batch where every attempted PRD was parked: no completed product
work exists to send through post-drain QA.

`decide()` evaluates exactly this precedence and has a table test for every
row: unreadable/missing post-state -> `HALT`; durable pause intent/reason ->
`PAUSE`; drained plus zero completed PRDs plus untouched pending capabilities ->
`SKIP_CAPABILITIES`; drained plus a required pending capability ->
`RUN_CAPABILITY`; drained plus any failed required capability or attention ->
`HALT` nonzero for explicit CLI retry; drained plus all required capabilities
succeeded -> `COMPLETE`; changed `progress_fingerprint` plus a non-empty next
phase -> `CONTINUE` even when the provider exit is nonzero; credible future
rate limit within cap and
retry budget -> `WAIT`, beyond the time cap or after `rate_limit_retries` ->
`HALT`; bounded connectivity -> `WAIT`/`RETRY`, then
`HALT`; other untouched-session death -> `RETRY`, then `PARK` when a PRD exists
or `HALT` during bootstrap; repeated equal fingerprints -> `PARK` only with an
active PRD and -> `PAUSE` at bootstrap, with the workflow park saga deciding
the second-consecutive systemic halt. A live `running` capability is not
runnable; the effect layer reconciles ownership before `snapshot()`, and any
stale attempt becomes failed attention. Retry counters reset only after a
non-matching failure class or changed progress fingerprint. Final agent prose is
absent from every input type.

Every capability and completion row above is gated by `drained`; an ordinary
build/review/done snapshot with no required capabilities cannot complete by
vacuous truth. An unchanged successful session below `phase_repeat_limit`
returns `RETRY` with the incremented `next_phase_repeats`; the limit-crossing
decision alone becomes `PARK` or bootstrap `PAUSE`. A drained snapshot that
still contains a live `running` required capability returns `HALT`; ownership
must be resolved outside the pure table and the supervisor never launches a
duplicate attempt. No-progress permission or authentication failures return
`HALT`. An empty drained batch takes `SKIP_CAPABILITIES` only while required
pending entries remain; after the skip transition removes their applicability,
the next decision is `COMPLETE`.

`progress_fingerprint()` includes only workflow-owned progress facts: active
PRD, phase/next phase, task completion count, review cycle, completed-PRD count,
and capability status/attempt identity. It excludes raw revision,
`recovery.phase_fingerprint`, `recovery.phase_repeats`, all control notices,
and supervisor counters. The order is fixed: execute/reduce, reread state,
snapshot, call `decide()` (which returns `next_phase_repeats`), then persist the
fingerprint/repeat effect with the snapshot revision as compare-and-set. A
supervisor-authored revision bump therefore cannot manufacture progress.

```python
Effort = Literal["low", "medium", "high", "xhigh"]

    phase: Phase
    tier: str
    model: str
    effort: Effort
    timeout_seconds: int

    root: Path, phase: Phase, *, agent: str | None = None

```

`supervisor_settings(..., **explicit)` accepts exactly `runtime` as a
`RuntimeSettings`, `policy` as a `SupervisorPolicy`, and `phases` as a complete
build/review/done mapping of `PhaseSettings`; each replaces the corresponding
resolved section. Unknown keys, wrong types, and incomplete/non-routable phase
mappings raise `ConfigurationError`.

`[phases.PHASE]` accepts only `tier`, `effort`, and `timeout_seconds`.
`[agents.NAME.phases.PHASE]` may override only `tier` and `effort`.
`[agents.NAME.prompts]` accepts literal nonblank `build`, `review`, and `done`
prompt strings; prompts are not shell-expanded or formatted, and the existing
credential scanner rejects embedded secrets. `AgentSettings` gains the frozen
`prompts: Mapping[str, str]` field, and `ResolvedPhaseRoute.prompt` carries the
selected literal or `None`.
`ResolvedPhaseRoute.model` must equal `AgentSettings.tiers[tier]`; unknown tiers,
unsupported effort, booleans-as-numbers, non-finite values, and nonpositive or
unbounded timeouts fail before launch. Defaults are build/done=`sonnet`,
review=`opus`, neutral effort `high`, and bounded per-phase timeout; the driver
maps these neutral values to native flags and never silently drops one.

`src/ovcaq/drivers/base.py` sets `DRIVER_API_VERSION = 2` and adds to

```python
def default_prompt(self, phase: str) -> str: ...
```

`ClaudeDriver.default_prompt()` returns the launcher-owned workflow entry prompt.
For build/review/done that prompt is the literal `/autopilot:run-autopilot`;

`src/ovcaq/runtime/supervisor.py`:

```python
class CapabilityRunnerResolver(Protocol):
    def __call__(self, capability: CapabilityEntry) -> CapabilityRunner: ...

@dataclass(frozen=True, slots=True)
class SupervisorOutcome:
    exit_code: int
    decision: SupervisorDecision
    sessions_attempted: int

class Supervisor:
    def __init__(
        self,
        root: Path,
        *,
        store: StateStore,
        driver: AgentDriver,
        settings: SupervisorSettings,
        capability_runner: CapabilityRunnerResolver,
        clock: Clock,
        sleeper: Callable[[float], None],
    ) -> None: ...
    def run(self) -> SupervisorOutcome: ...
    def run_once(self) -> AttemptResult: ...
    def apply(self, decision: SupervisorDecision) -> bool: ...
```

`run()` acquires the existing `RunLock`, publishes fleet/run ownership, rejects
unacknowledged emergency state failure, enters `supervisor_signal_scope()`, and
loops until a terminal decision. Each workflow attempt uses a fresh
`SessionPaths`, `OwnedProcess.spawn(shell=False)`, `Watchdog`, raw-first
`SessionEvidenceWriter`, driver decode, normalized observation persistence,
driver summary, and `publish_session_summary()`. Decode failures become
`raw.unknown`/normalized failure evidence and do not crash the loop. A state
read failure prevents another launch. `SIGINT`/`SIGTERM`/`SIGHUP` stop the owned
process group, publish the terminal summary and metric, clean matching registry
records, and return the shell-compatible signal exit code.

`src/ovcaq/runtime/capability.py`:

```python
@dataclass(frozen=True, slots=True)
class CapabilityRequest:
    name: str
    root: Path
    batch_id: str
    attempt_id: str
    session: SessionPaths
    timeout_seconds: int

@dataclass(frozen=True, slots=True)
class CapabilityExecution:
    success: bool
    session_id: str
    detail: str | None

class CapabilityRunner(Protocol):
    def run(self, request: CapabilityRequest) -> CapabilityExecution: ...

class CapabilityService:
    def start(
        self, name: str, *, expected_revision: int | None = None
    ) -> CapabilityAttempt: ...
    def finish(
        self,
        name: str,
        attempt_id: str,
        execution: CapabilityExecution,
        *,
        expected_revision: int | None = None,
    ) -> State: ...
    def reconcile(self, name: str) -> State: ...
    def retry(self, name: str, runner: CapabilityRunner) -> State: ...
```

`start()` accepts only required `pending`, creates a globally unique attempt ID,
appends exactly one `running` attempt, and atomically sets the capability
`running`. The explicit `retry()` entry point alone may advance `failed` to a
new `running` attempt after ownership reconciliation; the supervisor loop exits
nonzero on failure and never auto-retries it. `finish()` requires the current
matching attempt. Success
sets attempt/capability `succeeded`; when every required capability succeeded it
sets `batch.status="completed"`, `batch.completed_at`, and clears capability
attention. Failure sets attempt/capability `failed`,
`batch.status="attention"`, and `control.attention` in one transaction without
changing `work`, `tasks`, `review`, or `batch.completed_prds`. Empty drains use
one compound mutation to set each pending entry `required=false` and
`status="skipped"`, then complete without calling a runner; pins and attempt
history remain intact.
`reconcile()` treats a running attempt as live only when its retained session
metadata still proves the owning PID identity; stale ownership becomes a failed
attempt with actionable attention. `retry()` refuses a live owner, reconciles a
stale owner, then starts one new attempt. `CapabilityService` owns creation of
the capability `SessionPaths`, its pending/final metric, runner invocation, raw
evidence, and finalization for both the supervisor drain path and the standalone
CLI retry path; neither caller can omit evidence or metrics. There is no
launcher-specific logic in this service.

`src/ovcaq/runtime/session.py`:

```python
@dataclass(frozen=True, slots=True)
class SessionMetric:
    schema_version: Literal[1]
    kind: Literal["phase", "capability"]
    run_id: str
    session_id: str
    batch_id: str
    prd: str | None
    phase_launched: Phase | None
    capability: str | None
    phase_end: NextPhase | None
    decision: str | None
    started_at: str
    finished_at: str | None
    wall_seconds: float | None
    model: str | None
    usage: Mapping[str, int | float | bool | None] | None

def publish_session_metric(
    paths: RuntimePaths, session: SessionPaths, metric: SessionMetric
) -> None: ...
def reconcile_metrics(paths: RuntimePaths) -> tuple[SessionMetric, ...]: ...
```

The canonical metric is one atomically published row in that session's
`metrics.jsonl`. Immediately before child spawn, `run_once()` publishes its
pending form (`decision`, `phase_end`, `finished_at`, and `wall_seconds` null).
After `run()` computes the decision, an outer `finally` atomically replaces that
same one-row file with the finalized form; a finalized row cannot be replaced.
`reconcile_metrics()` validates all retained session rows,
deduplicates by `session_id`, orders by start/session identity, and atomically
replaces the aggregate `RuntimePaths.metrics`. A pending row found at startup is
normalized in the aggregate view as `decision="interrupted"` without rewriting
the retained canonical evidence. Reconciliation runs before every launch, so a
host crash after spawn, during decision, or between canonical finalization and
aggregate publication cannot lose or duplicate an attempted session.
For `kind="phase"`, `phase_launched` and `model` are required and `capability`
is null. For `kind="capability"`, `capability` is required while phase/model are
null. These are version-one fields in a newly introduced metric record, not a
migration of retained v1 state; the tolerant legacy report loader continues to
accept characterized legacy rows.

CLI surface, all generated by `build_parser()`:

```text
ovcaq run --no-tui [--agent NAME]
ovcaq pause [--reason TEXT]
ovcaq resume
ovcaq stop
ovcaq capability retry NAME
```

`run` requires `--no-tui` in this PRD and owns the foreground process; PRD
00008 later adds TTY/TUI behavior. `pause` commits boundary intent and returns
zero. `resume` clears that intent and returns zero. `stop` validates published
supervisor process identity before signalling and fails closed on missing or
mismatched identity. `capability retry` returns nonzero while a live attempt
owns the capability or when the attempt fails; successful retry never reopens
workflow phases. Machine output uses the existing JSON/error-code envelope.

## Data flow

1. CLI resolves the project, runtime paths, agent, driver, routing, and policy;
   preflight rejects invalid state, unhealthy driver, emergency evidence, or a
   duplicate run before any child launch.
2. `Supervisor.run()` reconciles any running capability ownership, reads state,
   and calls pure `snapshot()`. Boundary pause is consumed before launch. Only a
   drained batch is routed to capability handling: an empty drain takes
   `SKIP_CAPABILITIES`, a pending required capability takes `RUN_CAPABILITY`, a
   failed capability exits nonzero with attention, and satisfied requirements
   take `COMPLETE`. Otherwise `resolve_phase_route()` plus
   `driver.default_prompt()` builds the existing neutral `LaunchRequest`.
3. The supervisor creates private session evidence, publishes supervisor/run
   identity, starts one owned process group, and streams each stdout line to raw
   evidence before attempting decode. Normalized observations are separately
   retained; the driver reduces them to `SessionSummary`.
4. The supervisor rereads committed state. `decide(before, result, counters,
   policy)` chooses one action from state plus normalized summary. A changed
   workflow fingerprint beats noisy exit status; supervisor-only revision
   changes do not. The resulting fingerprint/repeat count is persisted only
   after that decision under compare-and-set. Prose is never inspected.
5. The effect layer either waits within a bound, relaunches a fresh session,
   calls the existing workflow park saga, records/clears pause intent, runs one
   capability attempt, archives the terminal batch, or exits loud. Every
   durable change goes through `StateStore`/`StateService`.
6. One pending canonical `SessionMetric` is published before spawn, atomically
   finalized after the decision, and reconciled into the aggregate ledger.
   Run/fleet ownership is
   removed only after child cleanup and evidence publication.
7. On non-empty drain, the capability service advances pending -> running ->
   succeeded/failed. Failure leaves drained workflow state intact, exposes
   attention, and terminates this supervisor run nonzero after exactly one
   attempt; only an independent `capability retry` starts again from failed,
   without invoking a workflow phase.

## Alternatives considered

1. Chosen: a pure decision module plus a thin effectful supervisor. This makes
   every continuation reproducible from a table, keeps provider code at the
   edge, and lets fake clocks/drivers exercise the full loop without subprocess
   timing.
2. Smallest diff: copy the legacy `Loop`/mixins and replace its paths. Rejected
   because it preserves marker/prose/log parsing, provider commands, and
   swallowed agoge failure—the defects this PRD exists to remove. The larger
   typed split buys testable precedence and the state-plus-summary boundary.
3. Encode lifecycle decisions as methods on `StateStore`. Rejected because the
   store owns durability, not policy; it would couple state persistence to
   process/retry semantics and make the TUI/state service a second supervisor.
4. Keep aggregate append-only metrics as the only source. Rejected because a
   crash can leave a partial row or make retry append twice. Per-session atomic
   canonical rows plus deterministic reconciliation provide exactly-once
   identity and retain the existing aggregate consumer.

## Risks & edge cases

- Productive state plus a nonzero child exit must continue; untouched state plus
  cheerful final prose must not. Tests construct both explicitly.
- State can change between snapshot and effect. Every compound mutation accepts
  `expected_revision`; conflicts cause a fresh read/decision, never replay of a
  stale effect.
- Rate-limit resets may be missing, stale, repeated, or beyond the wait cap.
  Only a normalized credible future reset waits, always with injected/bounded
  time and a separate retry budget.
- Connectivity, timeout, death, repeated fingerprints, park, and the second
  consecutive systemic park have independent counters and exhaustion tests;
  no loop or evidence growth is unbounded.
- A decoder may emit unknown observations or throw after raw bytes landed. Raw
  evidence stays authoritative and the attempt becomes an unknown/agent failure
  rather than crashing the supervisor.
- Stop/pause races are resolved at boundaries: stop signals the proven process
  owner immediately; pause is durable and consumed before the next launch.
- Capability finish/retry races use attempt ID plus expected revision. A live
  owner blocks retry; an unverifiable owner is reconciled to failed attention,
  never assumed dead silently.
- Capability failure must not mutate drained PRDs. Tests compare the serialized
  `work`, `tasks`, `review`, and `completed_prds` subtrees before and after
  fail/retry.
- A crash after spawn but before metric finalization leaves the pre-spawn
  pending row, which startup reconciliation projects as interrupted; a crash
  after finalization but before aggregate replacement is likewise repaired.
  Malformed retained rows are surfaced as runtime-format attention, not skipped
  silently.
- Likely next changes are PRD 00008 TUI attachment, PRD 00009 a Codex driver,
  and PRD 00010 real launcher capability provisioning. The design exposes
  shared run/decision models for the TUI, keeps driver prompt/native mapping at
  the edge, and injects a generic capability runner so none requires a second
  lifecycle algorithm.
